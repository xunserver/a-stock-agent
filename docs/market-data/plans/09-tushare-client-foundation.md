# Plan 09: Tushare Client Foundation

Status: not started

Release boundary: internal work package; not independently deployable

## Objective

Build the shared Tushare SDK boundary, safe configuration, request governor,
table conversion utilities, typed error translation, and test fixtures required
by every Tushare capability Adapter. Do not register Tushare as a production
source and do not change source-order defaults in this plan.

## Deliverables

### 1. Dependency

Add `tushare>=1.4.24,<2` to ingest. Lockfile changes must be generated by the
repository package manager and contain no unrelated upgrades.

### 2. Client factory

Implement one factory that:

- reads `TUSHARE_TOKEN`, optional `TUSHARE_API_URL`, timeout, and max RPM;
- fails with `AuthenticationFailed` when a selected source lacks a token;
- validates HTTPS URLs and rejects query credentials/userinfo;
- creates the SDK client without globally mutating `ts.set_token` state;
- sets `_DataApi__http_url` only inside this module when a custom URL exists;
- exposes a redacted endpoint host label for logs;
- supports injected fake clients and clocks in tests.

No public API returns or logs the token.

### 3. API executor

Provide a small executor used by all Tushare Adapters. It must support normalized
parameters and field lists, process-wide RPM budgeting, bounded retry hooks,
elapsed/request metrics, and typed translation to `RateLimited`,
`AuthenticationFailed`, `SourceUnavailable`, and `InvalidSourcePayload`.

Do not implement cross-source fallback here. The existing fallback module owns it.

### 4. Source-table utilities

Implement dependency-contained conversion from pandas/DataFrame-like responses
to plain records. Normalize pandas missing values to `None`, reject non-tabular
payloads, preserve explicit zeroes, parse `YYYYMMDD`, and provide strict helpers
for finite numbers, optional strings, required columns, row limits, deterministic
sorting, and duplicate detection. No pandas object may cross the Adapter seam.

### 5. Pagination primitive

Provide a deterministic utility that repeats an API call by an Adapter-supplied
page/range planner, detects a full page at the documented limit, de-duplicates by
an Adapter-supplied key, and returns coverage/request metadata. Do not assume that
every Tushare API supports offset pagination.

### 6. Architecture rule

Extend the architecture check so production imports of `tushare` and SDK private
attribute access are allowed only under `providers/tushare/`. Add a regression
test or self-test demonstrating detection outside the approved directory.

## Required tests

- official-default and custom-endpoint client construction;
- missing token, rejected token, HTTP URL, embedded credentials, malformed URL;
- token redaction from repr, logs, exceptions, and attempt summaries;
- 429/rate-limit, timeout, transport, auth, malformed payload translations;
- zero/NaN/NaT/None/string/date conversion;
- duplicate, truncation, multiple-page, and conclusive-empty behavior;
- request governor under injected clock/sleep without real waiting;
- architecture violation detection.

No unit test makes a network call.
